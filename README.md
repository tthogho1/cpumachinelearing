# CPU Machine Learning — US Inflation Forecasting

Early-stage Python project that downloads economic time series (CPI, unemployment,
interest rates, industrial production, etc.) and forecasts US CPI inflation several
months ahead using CPU-only scikit-learn models (no GPU required).

## Project structure

```
fetch_economic_data.py   # Downloads World Bank + FRED data -> data/*.csv
forecast_common.py       # Shared feature engineering, model definitions, scoring, save/load
train_model.py           # Backtest + train models, optionally save them (--save-model)
predict_model.py         # Load a saved model and evaluate / forecast without retraining
data/                    # Downloaded & merged CSVs (regenerated by fetch_economic_data.py)
output/                  # Generated plots and saved model bundles (gitignored)
```

## Setup

A virtualenv is recommended (Python 3.10+).

```sh
python -m venv .venv
source .venv/bin/activate          # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

No API key is required for either data source, but network access is needed.

## 1. Fetch data

```sh
python fetch_economic_data.py                  # World Bank (default JPN) + FRED -> data/
python fetch_economic_data.py --country USA     # World Bank country, ISO3 code
python fetch_economic_data.py --out other_dir   # change output directory
```

This produces, among others, `data/fred_monthly_merged.csv` — a monthly table merging:

| Column | Source series | Description |
|---|---|---|
| `us_cpi` | CPIAUCSL | US Consumer Price Index |
| `us_unemployment_pct` | UNRATE | US unemployment rate (%) |
| `us_fed_funds_pct` | FEDFUNDS | Effective federal funds rate (%) |
| `us_industrial_production` | INDPRO | US industrial production index |
| `us_10y_treasury_pct` | DGS10 | 10-year US Treasury yield (%) |
| `jp_cpi` | JPNCPIALLMINMEI | Japan CPI (stopped updating 2021-06; unused) |

## 2. Train & backtest a model

```sh
python train_model.py                                   # 12-month-ahead backtest (~15s)
python train_model.py --horizon 6 --test-start 2010-01-01
python train_model.py --horizon 12 --save-model output/models_h12.joblib
```

This builds lagged macro features, runs an expanding-window walk-forward backtest
(refitting yearly, no look-ahead leakage), prints out-of-sample MAE/RMSE for each
model vs. a "no change" baseline, reports feature importance, prints the latest
forecast, saves a plot to `output/`, and — if `--save-model` is given — fits final
models on all data and persists them (models + feature names + horizon) via joblib.

## 3. Reuse a saved model

```sh
python predict_model.py --load-model output/models_h12.joblib
```

Loads the saved model bundle and immediately evaluates it against `--data` and prints
the latest forecast — no retraining. Useful once you have a model you're happy with
and just want fresh predictions as new data arrives.

## Design notes

- **No look-ahead:** a feature at row `t` only uses data from month `t` or earlier.
  The target at row `t` becomes known at `t + horizon`, so training at forecast
  origin `T` is limited to rows `<= T - horizon`.
- **Target is the change** in YoY inflation (`infl_yoy[t+h] - infl_yoy[t]`), not the
  level, so tree models aren't limited to inflation ranges seen in training, and the
  `no_change` baseline is simply predicting 0.
- Results are reported relative to the `no_change` baseline (`RMSE_vs_no_change`); a
  model is only useful if this ratio is below 1.
- Models: Ridge regression (`RidgeCV`), `RandomForestRegressor`, and
  `HistGradientBoostingRegressor` — all CPU-friendly scikit-learn estimators.
